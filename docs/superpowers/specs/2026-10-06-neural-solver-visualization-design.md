# 神经网络决策与可视化设计

## 目标

为数字华容道加入一个可训练的 PyTorch 神经网络，并把模型在每个棋盘状态下的可观察决策信号展示在 Pygame 窗口中。用户可以先离线训练模型，再启动游戏以 AI 模式逐步或自动观看解题过程，同时得到一份可追溯的训练报告。

第一版支持 4×4 棋盘，与当前项目的 `ROW_NUMBER` 和 `COL_NUMBER` 配置保持一致。模型输出四个方向的动作分数，动作方向统一从空白格视角定义为上、下、左、右。游戏中的解释面板展示动作概率、Q 值、合法性、启发式变化和最终选择，不把隐藏层信号描述成自然语言思维。

## 方案选择

采用混合训练路线。监督阶段使用现有 A* 求解器为随机可解局面标注第一步动作和剩余解题步数，快速得到稳定的策略初始化。强化阶段将棋盘封装为纯 Python 环境，使用经验回放和目标网络进行 DQN 微调；只有独立评估确实改善时才采用微调后的模型，否则保留监督模型并在训练报告中说明。

相较于纯 DQN，这种路线能在有限 CPU 资源下较快得到可演示模型；相较于只做模仿学习，它保留了后续让模型通过环境反馈改进的路径。模型不替代现有 A*，A* 仍作为数据标注器、评估基线和模型失败时的诊断工具。

## 系统架构

### 模型

模型由共享编码器、策略头和 Q 头组成。编码器输入为 16 个格子的 16 维 one-hot 数字身份编码，另加空白格行列、归一化曼哈顿距离、线性冲突数量等全局特征。推荐的默认结构为：

```text
输入特征 -> Linear(特征数, 128) -> ReLU -> Linear(128, 64) -> ReLU
                                          |                |
                                   策略头 Linear(64, 4)   Q 头 Linear(64, 4)
```

策略头和 Q 头的四个输出都对应 `UP`, `DOWN`, `LEFT`, `RIGHT`。监督训练使用策略头的交叉熵，并让专家动作的 Q 值拟合负的 A* 剩余步数，使 Q 值具有“越大越接近目标”的方向；DQN 阶段再使用四个动作的时序差分目标微调 Q 头。运行时用策略 logits 的 softmax 作为动作概率，用 Q 头作为动作价值参考。非法动作会在选动作前屏蔽，避免模型输出越界移动。

### 数据流

1. 数据集生成器从目标盘开始执行随机合法打乱，过滤重复状态并固定随机种子。
2. 对每个局面调用 A* 得到第一步动作和剩余步数；无法求解的状态不进入数据集，并计入生成统计。
3. 监督训练按训练集和验证集分离数据，优化策略交叉熵与专家动作 Q 值回归损失。
4. DQN 阶段通过 `PuzzleEnvironment` 执行动作，使用完成奖励、非法动作惩罚和距离改善奖励构造回报。
5. 训练结束后在独立随机局面上评估模型，保存模型、配置、指标和 Markdown 报告。
6. Pygame 启动时通过 `agent.py` 加载模型；每次需要决策时返回一条完整 `DecisionTrace`，渲染层只消费这条记录。

### 代码边界

| 文件 | 责任 |
| --- | --- |
| `src/ai/encoding.py` | 棋盘状态编码、动作枚举和方向映射 |
| `src/ai/model.py` | PyTorch 网络、前向输出和模型序列化 |
| `src/ai/environment.py` | 无副作用的棋盘状态转移、奖励和终止条件 |
| `src/ai/dataset.py` | 随机局面生成、A* 标注、训练/验证集保存 |
| `src/ai/train.py` | 监督训练、DQN 微调、评估、报告生成 CLI |
| `src/ai/agent.py` | 模型加载、合法动作屏蔽、动作选择和 `DecisionTrace` |
| `src/render/ai_panel.py` | Pygame 解释面板和候选动作条形图 |
| `src/render/window.py` | 接入 AI 模式、快捷键、动画和面板布局 |
| `models/` | 默认模型与训练元数据；目录内容不提交大型临时检查点 |
| `reports/` | 每次训练产生的 Markdown 报告和指标 JSON |

## 训练接口

训练模块提供以下命令：

```bash
uv run python -m ai.train --stage imitation --samples 2000 --seed 42
uv run python -m ai.train --stage dqn --checkpoint models/imitation.pt --episodes 2000
uv run python -m ai.train --stage eval-only --checkpoint models/best.pt
```

默认参数必须在命令输出和报告中回显，包括棋盘尺寸、样本数、打乱深度、学习率、批大小、训练轮数、随机种子、设备（CPU/CUDA）和当前 Git 提交号。训练命令在 `models/` 和 `reports/` 不存在时自动创建目录。

监督阶段保存最佳验证准确率模型。DQN 阶段保存独立评估成功率最高的模型，并同时保留监督模型作为回退。模型文件包含网络权重、归一化参数、动作顺序、训练阶段和版本号，加载时校验棋盘尺寸和动作协议。

## 决策轨迹与界面

`DecisionTrace` 至少包含：当前棋盘状态、空白格位置、四个动作的合法性、策略概率、Q 头动作值、每个合法动作的下一状态启发式分数、选择的动作、置信度、推理耗时和累计步数。它同时用于界面刷新、日志记录和报告中的示例决策。

AI 模式使用右侧解释面板。顶部显示当前模式、模型版本、步数、置信度和推理耗时；中部用四行横向条形图展示四个候选动作，非法动作置灰，最终动作高亮；棋盘区域用箭头标示空白格移动方向，并用颜色表示启发式改善或退化；底部显示最近若干条决策记录。窗口缩放时棋盘和面板分别按区域重新计算尺寸，不允许文字覆盖棋盘。

快捷键约定如下：`A` 在手动和 AI 模式间切换，空格暂停/单步，`T` 显示或隐藏解释面板，`R` 重新生成可解棋盘，`Esc` 保留现有重置行为。AI 模式下模型文件缺失、版本不兼容或推理异常时显示明确错误并自动回退到手动模式。

## 训练报告

每次训练生成 `reports/training-<timestamp>.md` 和同名 `metrics.json`。Markdown 报告包括：运行元数据、数据集生成统计、模型结构、监督训练曲线摘要、DQN 曲线摘要、训练/验证损失、动作准确率、合法动作准确率、独立局面成功率、平均解题步数、非法动作率、平均决策耗时、与 A* 和随机策略的对照，以及一到三条完整 `DecisionTrace` 示例。

报告必须区分监督模型和 DQN 微调模型，明确指出最终采用哪个检查点及原因。若 DQN 阶段没有改善，报告记录失败指标和回退原因；不得用微调结果覆盖更好的监督模型。`metrics.json` 使用稳定字段名，便于后续绘图或批量比较实验。

## 测试与验收

单元测试覆盖编码器的维度和确定性、目标盘编码、动作方向映射、环境合法/非法转移、奖励计算、模型输出形状和 `DecisionTrace` 完整性。训练测试使用很小的数据集和少量轮数，验证命令能生成模型与报告，不要求达到最终成功率。

集成测试在 `SDL_VIDEODRIVER=dummy` 下启动 Pygame，加载测试模型，执行一次 AI 单步并确认解释面板完成渲染。评估测试确认模型不会执行非法动作，目标盘立即终止，且手动模式在没有模型文件时仍可使用。运行 `python -m compileall src`、针对 AI 模块的测试和无窗口冒烟测试作为交付前检查。

## 非目标与限制

第一版不追求证明神经网络得到最短解，也不把隐藏层激活解释成因果证明。A* 仍然是最可靠的基线；模型可能在困难随机局面失败，报告必须显示这种失败。训练默认面向当前 4×4 棋盘，不承诺任意行列数都能直接复用网络结构。
